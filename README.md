# AI Vendor Trust Pack

This project is a sample security questionnaire and diligence support pack for a fictional AI-for-finance vendor called FinSight AI. It includes five representative bank diligence responses, a control-theme mapping, and an evidence checklist for preparing AI vendor trust materials.

## Why banks ask detailed security and AI governance questions

Banks are regulated institutions, so they need to understand the risks introduced by third-party software vendors before onboarding them. For AI vendors, that review often goes beyond standard security questions and includes how customer data is handled, whether data is used for model training, how tenant isolation works, how AI outputs are logged, and what controls exist for AI-specific risks like prompt injection. Clear, evidence-backed responses help both the bank and the vendor move diligence forward with fewer follow-up cycles.

## What is included

- `README.md`: Project overview and context
- `security-questionnaire-response-pack.md`: Five representative diligence responses covering baseline assurance, AI data use, internal access, tenant isolation, and AI governance
- `control-theme-mapping.md`: Lightweight mapping table connecting questionnaire areas to relevant frameworks and evidence artifacts
- `evidence-checklist.md`: Practical checklist of artifacts an AI vendor should prepare for bank diligence, organized by area and internal owner

## Development process

I built this project as a learning exercise to understand how customer trust and security teams respond to bank vendor diligence. I used AI tools to generate sample questionnaire prompts, then drafted my own responses using publicly available trust center materials and security documentation. After that, I used AI tools to pressure-test the responses for clarity, accuracy, tone, and overclaiming. I selected the final questions, reviewed the control framing, and edited the materials to keep the responses practical, evidence-backed, and appropriately caveated.
